\section{Introducción}

El presente informe describe el avance realizado en los dos primeros sprints del proyecto \textbf{SigmaFit}, una plataforma web de entrenamiento adaptativo. El objetivo principal del sistema es permitir que un usuario registre su perfil inicial, genere una rutina semanal personalizada y lleve seguimiento de sus entrenamientos mediante un tracker en vivo.

El trabajo se organizó de forma incremental. En el \textbf{Sprint 1} se construyó la base técnica y funcional del sistema: entorno, base de datos, backend inicial y onboarding. En el \textbf{Sprint 2} se implementó el valor principal de la aplicación: el coach virtual para generar rutinas y el tracker de entrenamiento para registrar series, peso y descanso.

% =========================================================
\section{Idea base del proyecto}

SigmaFit nace como una aplicación orientada a usuarios que desean organizar su entrenamiento de forma más estructurada. A diferencia de una aplicación estática de rutinas, la idea del proyecto es que el sistema use la información del usuario para generar una planificación acorde a su objetivo, experiencia y disponibilidad.

\begin{tcolorbox}[title=\textbf{Idea central}]
El usuario completa un perfil inicial, el sistema genera una rutina semanal y luego el usuario registra su entrenamiento real. Esta información servirá como base para futuras mejoras, como ajuste adaptativo por fatiga, RPE y sobrecarga progresiva.
\end{tcolorbox}

% =========================================================
\section{Metodología de trabajo}

El equipo trabajó siguiendo una organización por sprints. Primero se definió el backlog en Trello, separando las funcionalidades principales por prioridad. Luego se documentaron casos de prueba en TestRail para transformar las historias de usuario en criterios verificables.

Posteriormente, se usó Codex como apoyo para implementar las funcionalidades planificadas. Cada sprint fue desarrollado con una meta concreta, manteniendo pruebas, documentación y compatibilidad con Docker.

% =========================================================
\section{Arquitectura general implementada}

La aplicación quedó organizada en tres bloques principales:

\begin{itemize}
    \item \textbf{Frontend:} aplicación web desarrollada con React, TypeScript, Vite, Tailwind CSS, TanStack Router y Zustand.
    \item \textbf{Backend:} API desarrollada con Node.js, TypeScript, Express, PostgreSQL mediante \texttt{pg} y validación con \texttt{zod}.
    \item \textbf{Base de datos:} PostgreSQL con scripts SQL versionados para inicializar tablas y datos base.
\end{itemize}

Además, se integró \textbf{Docker Compose} para levantar el frontend, backend y base de datos con un solo comando.

\section{Sprint 1: Base del sistema y onboarding}

\subsection{Objetivo del Sprint 1}

El objetivo del Sprint 1 fue construir la base mínima funcional del sistema. Antes de implementar rutinas o seguimiento de entrenamiento, era necesario tener un entorno ejecutable, una base de datos inicial, un backend y una pantalla de perfilado.

\subsection{Historia de usuario trabajada}

\begin{tcolorbox}[title=\textbf{US-01: Onboarding y Perfilado}]
Como usuario nuevo, quiero completar un cuestionario inicial para definir mi objetivo de entrenamiento, mi nivel de experiencia y los días disponibles, para que el sistema pueda generar rutinas acordes a mi perfil.
\end{tcolorbox}

\subsection{Por qué se implementó primero}

Esta historia fue priorizada porque el perfil del usuario es la entrada principal para el resto del sistema. Sin conocer el objetivo, nivel y disponibilidad del usuario, el coach virtual no puede generar rutinas personalizadas.

\subsection{Trabajo realizado}

En este sprint se implementaron las siguientes actividades:

\begin{itemize}
    \item Configuración de Docker Compose para levantar frontend, backend y PostgreSQL.
    \item Creación del backend mínimo con endpoints de salud, perfil y onboarding.
    \item Diseño inicial de base de datos con tablas para usuarios, perfiles y ejercicios.
    \item Script de datos iniciales con usuario demo y catálogo base de ejercicios.
    \item Pantalla de onboarding para registrar objetivo, experiencia y días disponibles.
    \item Validaciones del formulario de onboarding.
    \item Persistencia del perfil inicial.
    \item Redirección obligatoria al onboarding cuando el usuario no tiene perfil completo.
    \item Acceso al dashboard cuando el usuario ya completó el onboarding.
\end{itemize}

\section{Sprint 2: Coach virtual y tracker de entrenamiento}

\subsection{Objetivo del Sprint 2}

El objetivo del Sprint 2 fue implementar el núcleo funcional de SigmaFit: la generación de rutinas y el seguimiento del entrenamiento. Con el perfil del usuario ya disponible desde el Sprint 1, el sistema ahora puede generar una rutina semanal y permitir que el usuario registre su progreso.

\subsection{Historias de usuario trabajadas}

\begin{tcolorbox}[title=\textbf{US-02: Motor de generación de rutinas}]
Como usuario con perfil configurado, quiero que el coach virtual genere automáticamente un bloque de entrenamiento semanal, para tener una rutina estructurada y basada en el catálogo oficial de ejercicios del sistema.
\end{tcolorbox}

\begin{tcolorbox}[title=\textbf{US-03: Tracker de entrenamiento en vivo}]
Como usuario durante una sesión activa, quiero marcar series, registrar el peso levantado y visualizar un temporizador, para gestionar mis tiempos de descanso y llevar un registro exacto de mi progreso.
\end{tcolorbox}

\subsection{Por qué se implementó en segundo lugar}

El Sprint 2 depende directamente del Sprint 1. Para generar una rutina, el sistema necesita conocer el objetivo, experiencia y días disponibles del usuario. Por eso, primero se implementó el perfilado y luego se construyó el coach virtual.

\subsection{Trabajo realizado}

En este sprint se implementaron las siguientes actividades:

\begin{itemize}
    \item Generación real de rutinas desde backend.
    \item Algoritmo determinístico de coach virtual basado en objetivo, experiencia y días disponibles.
    \item Consulta del catálogo de ejercicios desde la base de datos.
    \item Persistencia de rutinas activas en PostgreSQL.
    \item Consulta de rutina activa desde dashboard y workout.
    \item Creación de sesiones de entrenamiento por día de rutina.
    \item Registro de series completadas, peso levantado y unidad.
    \item Temporizador de descanso en frontend al completar una serie.
    \item Cierre de sesión con resumen básico.
    \item Fallback local controlado para que la interfaz no se rompa si el backend falla.
\end{itemize}

\subsection{Reglas usadas por el coach virtual}

El coach virtual no usa inteligencia artificial externa. Se implementó como un motor determinístico, simple y explicable para clase. La rutina se genera según tres variables principales:

\begin{itemize}
    \item \textbf{Objetivo:} hipertrofia, fuerza o pérdida de peso.
    \item \textbf{Nivel:} principiante, intermedio o avanzado.
    \item \textbf{Disponibilidad:} cantidad de días por semana.
\end{itemize}

\begin{table}[H]
\centering
\caption{Reglas principales de generación de rutinas}
\renewcommand{\arraystretch}{1.3}
\begin{tabularx}{\textwidth}{>{\bfseries}p{3cm} p{3cm} p{3cm} X}
\toprule
Objetivo & Repeticiones & Descanso & Enfoque \\
\midrule
Hipertrofia & 8--12 & 90 segundos & Volumen moderado orientado a crecimiento muscular. \\
Fuerza & 3--6 & 150--180 segundos & Menos repeticiones, mayor descanso y más series. \\
Pérdida de peso & 12--15 & 45--60 segundos & Mayor densidad de trabajo y descansos más cortos. \\
\bottomrule
\end{tabularx}
\end{table}

También se aplicaron divisiones semanales según días disponibles:

\begin{itemize}
    \item 2 días: Full Body A/B.
    \item 3 días: Full Body o Push/Pull/Legs según perfil.
    \item 4 días: Tren superior e inferior.
    \item 5 o 6 días: Push/Pull/Legs adaptado.
\end{itemize}

Al finalizar el Sprint 2, SigmaFit ya cuenta con su flujo principal: el usuario completa su perfil, genera una rutina semanal, consulta los días de entrenamiento e inicia una sesión para registrar su progreso. Esto convierte a la aplicación en un MVP funcional, no solamente una maqueta visual.

\section{Flujo funcional actual}

El flujo de uso actual de SigmaFit es el siguiente:

\begin{enumerate}
    \item El usuario abre la aplicación web.
    \item Si no tiene perfil completo, el sistema lo dirige al onboarding.
    \item El usuario selecciona objetivo, nivel y días disponibles.
    \item El sistema guarda el perfil.
    \item El usuario accede al dashboard.
    \item Desde el dashboard genera una rutina semanal.
    \item El sistema consulta el catálogo de ejercicios y genera una rutina.
    \item El usuario entra a la sección de workout.
    \item Selecciona un día de entrenamiento.
    \item Marca series, registra peso y usa el temporizador de descanso.
    \item Finaliza la sesión y revisa el resumen.
\end{enumerate}

% =========================================================
\section{Decisiones técnicas importantes}

\begin{itemize}
    \item Se decidió usar Docker Compose para facilitar que cualquier integrante pueda levantar el sistema completo.
    \item Se usó PostgreSQL para mantener persistencia real y no depender solo de mocks.
    \item El coach virtual se implementó con reglas determinísticas para que sea explicable y fácil de probar.
    \item Se mantuvo fallback local controlado para evitar que la interfaz se rompa si el backend no está disponible.
    \item No se implementó todavía RPE ni ajuste adaptativo avanzado, porque eso corresponde al Sprint 3.
    \item El temporizador de descanso se dejó en frontend, mientras que el registro de series sí se persiste cuando el backend está disponible.
\end{itemize}

% =========================================================
\section{Conclusiones}

En el Sprint 1 se construyó la base necesaria para que SigmaFit funcione como una aplicación real: entorno con Docker, backend, base de datos, seed inicial y onboarding. Esto permitió que el sistema registre la información mínima del usuario.

En el Sprint 2 se implementó el valor principal de la aplicación: la generación de rutinas mediante un coach virtual y el tracker de entrenamiento en vivo. Con esto, SigmaFit permite pasar del perfil del usuario a una rutina semanal y luego al registro práctico de una sesión de entrenamiento.

El proyecto queda preparado para continuar con el Sprint 3, donde se puede implementar el ajuste adaptativo por RPE, sobrecarga progresiva y lógica de descarga según la fatiga reportada por el usuario.
